# 证据与可复现性

论文中的每个关键数字都应能够回答三个问题：它从哪里来、由什么代码产生、当前是否仍然有效。

## 最小证据链

```text
原始输入
  → 数据处理记录
  → 代码与参数
  → 运行结果
  → 冻结数字/图表
  → 论文引用位置
```

任何一段缺失，都可能出现“论文有数字，但仓库无法重新得到”的问题。

## 应记录什么

- 输入文件的来源、版本或摘要值。
- 运行环境和关键依赖版本。
- 随机种子、训练/验证划分和参数。
- 执行命令、开始时间和退出状态。
- 主要指标、图表和中间诊断的输出路径。
- 结果冻结时间，以及对应代码和输入版本。

## 新鲜度规则

以下任一变化都会使下游证据失效：

- 修改原始或清洗后数据。
- 修改模型代码、特征或参数。
- 修改随机种子或数据划分。
- 修复会影响结果的缺陷。
- 替换图表的底层数据。

失效后应重新运行、重新检查并重新冻结，不能只手工修改论文中的个别数字。

## 基线与敏感性

基线证明复杂模型确实带来收益；敏感性分析证明结论不是某个任意参数的偶然产物。两者都属于证据链，而不是附加装饰。

至少检查：

- 主模型相对简单基线提升了什么。
- 指标变化是否具有实际意义，而不只是小数点差异。
- 合理范围内的参数扰动是否改变主要结论。
- 训练、验证或交叉验证结果是否一致。
- 异常样本和缺失值处理是否主导结果。

## 写作约束

- 不从聊天记录复制数字。
- 不把“代码成功运行”写成“模型有效”。
- 不只报告最优结果而隐藏基线和失败条件。
- 图表、表格和正文对同一指标使用相同定义与精度。
- 任何外部数据和文献都保留可核验来源。
