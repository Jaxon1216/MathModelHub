# 数学建模生命周期

完整建模不是“选一个算法然后写论文”，而是一条带决策点和回退条件的证据链。

## 1. 问题理解

产出：子问题清单、对象、目标、约束、已知数据、要求输出和统一符号表。

通过条件：团队能用自己的话说明每个子问题要求判断什么，而不是只复述题面。

## 2. 数据与假设

产出：数据字典、质量报告、必要假设、简化假设和适用边界。

通过条件：原始数据保持不变，所有清洗操作可追溯；每个重要假设都能说明为什么需要以及如何影响结论。

## 3. 模型路线

产出：一个可运行基线、一个主候选、必要时一个带触发条件的备选，以及评价指标。

通过条件：团队按目标和风险确认路线；复杂模型相对基线的价值可以被检验。

## 4. 实现与验证

产出：可复现代码、固定环境、机器生成结果、诊断图和敏感性分析。

通过条件：从干净环境可以完整运行；异常输入、假设风险和尺度问题已被检查。

## 5. 证据冻结

产出：允许写入论文的数字、图表、表格和结论快照。

通过条件：每项证据能定位到输入、代码版本和运行结果；变更后旧证据自动视为过期。

## 6. 写作与排版

产出：从问题到方法、结果和局限的完整论证，而不是代码执行日志。

通过条件：所有数字引用冻结证据；公式定义符号；图表在正文中被解释；结论没有超出模型支持范围。

## 7. 独立验收

产出：内容审查、证据审查和格式审查记录。

通过条件：任一审查发现阻断问题都返回对应阶段修复，修复后重新运行受影响的下游检查。

## 时间紧张时的优先级

优先保证完整、可解释、可复现的基线论证，再增加复杂模型。不要通过删除验证、伪造数据或隐藏局限来换取表面完整度。
