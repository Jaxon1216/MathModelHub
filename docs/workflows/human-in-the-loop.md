# 人在环审计型工作流

本页提炼 [MathModeling-skills](https://github.com/zhnnky329/MathModeling-skills) 的稳定方法论。实际 Skill 数量、Gate 名称和文件结构以上游版本为准。

## 核心分工

AI 负责：

- 题目和数据的结构化整理。
- 基线实现与候选方法的风险检查。
- 代码运行、结果落盘和一致性检查。
- 对异常、过时结果和缺失证据发出阻断。

人负责：

- 决定优化目标和真正重要的权衡。
- 选择模型路线并说明原因。
- 判断假设是否符合问题背景。
- 解释结果并承担最终提交责任。

## 推荐流程

1. **打地基**：解析题意、分类子问题、整理符号、假设和数据质量。
2. **生成候选**：为每个子问题形成主方案、可用基线和至多一个条件备选。
3. **风险探针**：在完整实现前检查数据覆盖、关键假设、输出退化、扰动敏感性与计算规模。
4. **人工路线确认**：团队根据目标和权衡选择路线，并把理由写入决策记录。
5. **实现审查**：验证语法、输入、方法一致性、可复现性和输出契约。
6. **冻结结果**：将论文允许引用的数字写入稳定快照；修改代码或数据后旧快照失效。
7. **写作与引用**：论文只能引用冻结证据，不能手抄聊天输出。
8. **独立终审**：内容、证据或格式任一审计失败，都不能标记为可提交。

## 风险探针应该回答什么

- 数据量和覆盖范围是否足以支持该方法？
- 方法的核心假设能否被检查？
- 输出是否退化成常数、极端类别或不可解释结果？
- 小幅扰动是否导致结论翻转？
- 完整运行的时间和资源是否适合比赛期限？
- 基线是否已经达到相近效果？

## 为什么先冻结数字

比赛后期最常见的问题不是没有结果，而是代码修复后论文仍保留旧数字。冻结机制把“论文允许引用什么”从口头共识变成显式状态；任何输入、代码或结果变化，都应触发重新运行和重新冻结。
