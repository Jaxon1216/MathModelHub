# 正式交付型工作流

本页提炼 [MathModel-Skill](https://github.com/yushui2022/MathModel-Skill) 的稳定方法论。具体 Skill 名称、脚本参数和目录结构可能随上游更新，使用时应以上游 README 为准。

## 适合什么任务

- 目标是形成可提交的正式论文，而不只是分析报告。
- 需要跨多轮对话恢复当前阶段。
- 需要把题目、代码、结果、论文和审查证据明确分层。
- 团队愿意在证据和格式门禁失败时停止推进。

## 推荐阶段

1. **预检**：确认题目、附件、依赖和输出目录状态。
2. **问题结构化**：拆解子问题、目标、约束、数据和交付物。
3. **路线形成**：记录模型、基线、假设、评价指标和失败条件。
4. **实现与运行**：代码写入固定输出区，真实运行后生成结果。
5. **证据门禁**：检查论文需要的数字、图表和结论是否都有来源。
6. **正式提纲**：证据稳定后再规划全文结构和篇幅。
7. **正式写作**：正文引用冻结后的结果，而不是聊天中的临时数字。
8. **格式门禁**：检查标题层级、公式、图表引用、引文和页面渲染。
9. **最终验收**：修复任何证据或格式问题后重新检查。

## 三条不可破坏的边界

### 输入与输出分离

原始题目和附件保持只读。当前赛题生成的代码、结果和论文全部进入约定输出目录，避免 Skill 包被比赛文件污染。

### 证据门禁早于正式写作

如果图表尚未生成、指标无法定位到运行结果、代码已经变化但报告未刷新，就不应进入正式成稿阶段。

### 格式通过不代表内容正确

Word 能打开、标题完整和公式可编辑，只证明文档结构可交付。模型合理性、结论边界和数据解释仍需要团队负责。

## 使用提醒

上游提供 Standard、Lite 以及可选 LaTeX 分支。不要在同一比赛项目中混装不同版本；先根据模型能力和交付格式选定一个版本。
